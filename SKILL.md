# HTML-схема

Тема: $ARGUMENTS

Результат — один файл `.html` без внешних ресурсов: переключатель темы, легенда, нумерованные разделы, в каждом сетка с дорожками, блоки, стрелки и строка первоисточников.

Папка скилла — `~/.claude/skills/html-flow-diagram/`:
- `template.html` — каркас: палитры, стили, переключатель темы, легенда, раздел с тремя дорожками, скрипт стрелок;
- `flowdiag` — проверка, снимки, версия без JS и прогон через санитайзер (`flowdiag --help`);
- `example/css-link-color.html` — готовая схема: каскад CSS и атака через `:visited`.

## Когда применять

- Процесс с несколькими участниками: браузер, сервер, хранилище.
- Ветки «да / нет», ошибки и отказы.
- Атаки и защиты: где проверка работает, где слабое место, что в плане.

## Порядок работы

1. **Факты.** Собрать факты до разметки. У каждого основание: `файл:строка`, ссылка на спецификацию или документацию, команда и её вывод. Непроверенное идёт в блок с текстом «Предположение: …».
2. **Файл.** Скопировать `template.html` к материалам задачи, без папки задачи — в рабочую папку сессии или `/tmp`. Палитры, стили, переключатель темы и скрипт остаются как в шаблоне; меняются `<title>`, легенда и разделы.
3. **Разделы.** Один раздел `h2` — один сценарий или вопрос: «1. Как …», «2. Атака: …». Подразделы — `h3` «2.1. …».
4. **Дорожки.** 2–3 колонки — участники или места действия. Первая строка сетки — заголовки `.lane`. Третья колонка может быть «Пояснения» для блоков `note`. Раздел атаки идёт без дорожек: атака → защита → итог слева направо, как раздел 2 примера.
5. **Блоки.** Класс задаёт тип:

   | Класс | Смысл |
   | --- | --- |
   | `step` | шаг процесса |
   | `atk` | атака, ошибка, внешнее действие |
   | `chk` | проверка или защита, которая работает |
   | `plan` | запланировано, не сделано |
   | `gap` | слабое место, ограничение, отказ |
   | `out` | итог ветки |
   | `note` | пояснение или пример к соседнему блоку |

   У блока есть `id`, явные `grid-column` и `grid-row`, заголовок `.tag` вида «Что · где» и 1–3 фразы. Код и HTTP — в `<pre><code>`, символы `<`, `>`, `&`, `"` экранируются. Широкий блок — `grid-column: 2 / 4`, высокий — `grid-row: 3 / span 2`. Ссылка на другой блок — `<a href="#id">`. Класс `center` у `.dg` выравнивает блоки по центру строки. В легенде остаются типы, которые есть на схеме.
6. **Стрелки.** Атрибут `.dg`: `data-edges="a>b|подпись;b>c"`, в подписи нет `;` и `|`. Скрипт выбирает путь: блоки на одной строке — горизонтальная стрелка, в одной колонке — вертикальная, иначе уголок от бока A к верху или низу B. Уголок проходит по строке A, поэтому клетки между A и колонкой B пустые. Подпись горизонтальной стрелки — одно короткое слово: промежуток между колонками 46 px. Длинная подпись ставится на вертикальную стрелку.
7. **Источники.** Последний элемент сетки — `.diagram-sources` в строке после блоков: первоисточники ссылками и пометка, какие примеры условные.
8. **Проверка.** `flowdiag check схема.html` — исправить всё, что он выводит, и повторить до `ok`. Затем `flowdiag shot схема.html` — снимки в светлой и тёмной теме; прочитать оба PNG один раз и исправить видимые дефекты.

## Текст

- Одна мысль — одна фраза; блок — 1–3 фразы.
- Слово называет действие: «передаёт», «проверяет», «удаляет». Термины полностью: `Content-Security-Policy`.
- Вывод с основанием: `файл:строка`, ссылка или вывод команды — в блоке или в `.diagram-sources`.
- Непроверенное начинается с «Предположение:».
- Условный пример помечен в блоке: «Адрес условный».
- Язык — язык запроса.

## Тема

Переключатель «Светлая / Тёмная» есть в каждой схеме. Палитры — переменные в `:root` и `:root[data-theme="dark"]`, начальная тема берётся из `prefers-color-scheme`. Новый цвет задаётся переменной в обеих палитрах: так блоки, стрелки, подписи и фон кода меняются вместе с темой. Перед сдачей проверяются снимки обеих тем.

## Показ

- Файл показывается инструментами `html_preview` и `html_render`, если они есть; иначе — путь к `.html` и PNG.
- Ответ: путь к файлу, по строке на раздел, что отмечено как предположение.

## Версия без JS для HTML-блока Markdown

HTML-блок `::: html` из `@diplodoc/html-extension` удаляет скрипты, поэтому раскладка и стрелки считаются заранее:

1. `flowdiag nojs схема.html` → `схема.nojs.html`: фрагмент `<style>` + разметка. Блоки стоят по координатам в px, стрелки — `div` и `span`, ширина 1040 px с горизонтальной прокруткой, шрифты Arial и Courier New.
2. `flowdiag sanitize схема.nojs.html` → `схема.nojs.sanitized.html`: прогон через санитайзер по умолчанию из `@diplodoc/html-extension` 2.9.7, пакет устанавливается в `~/.cache/flowdiag` при первом запуске. Число блоков, линий, наконечников и подписей до и после совпадает; удаляется только `@media`.
3. `flowdiag shot схема.nojs.sanitized.html` — снимки обеих тем.
4. Фрагмент вставляется в HTML-блок страницы (`::: html` … `:::`).

Переключатель темы здесь работает на CSS: две скрытые радиокнопки и `label`, тёмная палитра включается селектором `#fd-dark:checked ~ .theme-root`. Санитайзер удаляет `@media` и `color-scheme`, поэтому версия без JS открывается в светлой теме. После правки исходника экспорт повторяется.
